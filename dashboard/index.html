Every BLAKE2b seed, measured from outside

A single DNS response can only carry about 25 addresses before it hits the 512-byte UDP limit, so what one query returns says nothing about how much a seed knows. Asking fifteen times and counting distinct addresses does: a live crawler rotates through its database, a fixed list repeats itself exactly.

Live crawler — continuously connects to nodes and verifies them, so dead nodes drop out on their own. Fixed list — returns the same addresses every time; accurate only as long as someone maintains it by hand.

Reachable-node trend

The seeder records the sum of each node's uptime fraction over a rolling window. Read the 2-hour line as “how many nodes have effectively been continuously reachable” — it is a weighted figure, not a headcount, which is why it climbs as evidence accumulates rather than jumping to the node total.

What the fork is running

Advertised service bits

Every value carries bit 28 (0x10000000, NODE_BLAKE2B). The low digits are the ordinary Bitcoin service flags — c09 is network-limited, witness and v2 transport.

How a node finds the network

A new node has no peers and no chain, so it cannot verify anything yet. This is the one moment it has to trust an answer it cannot check — which is why who runs a seed matters more than how fast it is.

The fork needs more seed operators

Until recently the network bootstrapped off essentially one seed. Running another is an afternoon on a cheap VPS — but put it somewhere nobody else is: five seeds in one datacentre is one seed with five addresses, not five seeds. Geographic and provider diversity is the entire point. 

git clone https://github.com/LionThunderFingers/blake2b-seeder.git
cd blake2b-seeder
sudo CONTACT_EMAIL=you@example.com ./deploy/deploy.sh

Do not run one on your home connection: it publishes your address and puts an internet-facing service beside your node, wallet and mining.

This is a snapshot, not a live monitor. The figures are as of the timestamp above and do not update on their own. Uptime alerting for this seed runs separately as a dead-man's switch — if the host dies, the pings stop and the silence raises the alarm. A page can display health; it cannot detect failure.
